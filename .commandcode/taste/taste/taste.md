# Taste
- Always keep assets, `vendor` directories, build outputs, and generated bundles tracked and committed, so the repository always contains everything needed to run without building first — a build could fail against changed dependencies and lose runnable code. Only things that are not needed to run may be gitignored: `node_modules` and throwaway `scratch` directories. Confidence: 0.97
- Throwaway scratch/probe directories may live inside the repo as long as they are gitignored — no need to move temporary work to an out-of-repo session scratchpad. Confidence: 0.9
- Uses tab indentation consistently across source and test files. Confidence: 0.85
- Comments and docs should explain the reasoning ("why") behind non-obvious decisions rather than restating what the code does. Confidence: 0.75
- Prefers to measure before deciding: run the experiment and compare real numbers before changing a build, optimization, or default, rather than acting on a plausible-sounding recommendation. Confidence: 0.85
- Verify a guard by proving it *fails*, not only that it passes — e.g. tamper with the expected value and confirm the check reports the mismatch. A validation that only ever succeeds is untested. Confidence: 0.8
- Turns one-off investigations into committed, re-runnable scripts exposed as an npm script, so a claim (e.g. a size measurement) can be re-checked later instead of being remembered. Confidence: 0.75
- Prefers pins over receipts: third-party assets are locked to a committed expectation (sizes, hashes, and provenance) that the fetcher verifies against and fails loudly on mismatch, with an explicit deliberate flag (e.g. `--update`) to move the pin — never deriving the expectation from whatever was downloaded. Confidence: 0.85
- Avoids keeping a private copy of logic that upstream owns/drift from; prefers the fix upstream (e.g. an option on the upstream API) so every consumer benefits rather than vendoring a copy. Confidence: 0.7
- Prefers preserving correctness, safety checks, and actionable error diagnostics over marginal size/speed wins — will reject an optimization (e.g. `-d:danger`) that trades a real check for a few percent. Confidence: 0.7
- Keeps README/docs honest and current: records measured numbers and the decision behind them, and corrects earlier advice that turned out to be wrong rather than leaving it standing. Confidence: 0.7
- When adding a new package/library next to an existing sibling one, studies that sibling first and mirrors its conventions and public API surface (option names, the result-object shape, the asset-source model, aux tooling) rather than inventing new ones — following the same conventions family-wide. Confidence: 0.75
- Prefers to leave work uncommitted over committing a state that breaks the repo (e.g. a mid-refactor that no longer runs), and reports plainly what is broken and what remains rather than hiding it. Confidence: 0.6
- Communicates with terse one-word approvals (e.g. "go ahead") and expects the agent to carry a whole multi-step plan through to completion — executing, testing, and verifying before reporting — rather than checking in for confirmation at each step. Confidence: 0.6
- Licenses a package under MIT (or another clearly permissive licence) and says so explicitly: nothing is copyleft and nothing constrains the programs the user compiles; the LICENSE also spells out what it does *not* cover (bundled third-party assets). Confidence: 0.7
- Keeps third-party provenance in a dedicated `THIRD-PARTY-NOTICES.md` — a per-file table of what each artifact is and its licence, links upstream, and points back to where the exact bytes are pinned — and defers to a dependency's own notices rather than restating them, since only what the package actually ships is its licensing problem. Confidence: 0.7
- Package READMEs are written for the consumer: usage examples, API tables covering every option and result field, a side-by-side comparison of the alternatives with measured numbers, a "Notes" section of the caveats that actually bite, and a "Verification" section that states both what the tests cover and what they cannot. Confidence: 0.7
- Writes long, structured commit messages (a title, what changed and why, a "Verified:" line with the test results, and what is still outstanding) and, when they are too long for the shell command line, passes them via `git commit -F` from a file in the scratch directory. Confidence: 0.7
- Treats a sudden test failure as the environment until proven otherwise — checks free memory, closes stray browsers, re-runs the unchanged suite — rather than reporting a regression before the cause is known. Confidence: 0.7
- Smoke-tests the build artifacts themselves (e.g. loading the freshly built IIFE bundle into a vm and asserting the global and API it exposes) before committing them. Confidence: 0.65
- Wants shipped binary artifacts (e.g. the wasm compiler) to be reproducible rather than just a hash-pinned foreign prebuilt, but for a build that would need a foreign checkout plus a heavyweight multi-stage toolchain (e.g. Emscripten) prefers the procedure to be *documented* instead of executed in this repo — explicitly scopes work to "document how to build/upgrade it", treating pinning as a stopgap and written-down instructions as the acceptable end state. Confidence: 0.6
- Documentation that explains a package's own assets lives inside that package (e.g. `docs/ASSETS.md`), is added to the package's published `files` list, and is linked from the root README rather than duplicated there — so it travels and ships with the artifacts it describes. Confidence: 0.6
- Tooling that emits code or config (e.g. an `--update` mode printing asset receipts) prints in the exact format of the file it will replace — correct quoting, indentation, and shape, verified byte-identical — so applying its output is a clean diff rather than a reformat. Confidence: 0.6
- Validates written procedures by actually walking them step by step before committing the doc, and corrects the doc when reality differs (e.g. an "expect this to fail" step that in fact succeeds), rather than writing instructions from memory. Confidence: 0.6
